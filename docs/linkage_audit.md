# 关联风险审计（公开报告 × 合成辅助身份，私有 SQLite 审计库）v3

本文档描述第三个入口 `table-privacy-linkage`。它在 [v1 单次契约](contract.md)
产生的**公开报告**与一份**合成辅助身份 JSON 数组**之间做组合论（非概率）的关联
风险审计，结果写入一个**私有 SQLite 审计库**。它与连续发布台账完全独立：不读取
私有源表（v1 输入契约），也不读取 `table-privacy-series` 的 series 台账。

## 入口与输入

```sh
table-privacy-linkage \
  --report run/public/round1.json \
  --helpers fixtures/linkage/helpers_forced.json \
  --audit-db run/private/linkage_audit.sqlite
```

- `--report`：单次入口 `table-privacy` 写出的 **schema_version=1 公开报告**。
  只接受 `result.feasible=true` 且含已发布行的报告；不可行报告拒绝（退出 2）。
- `--helpers`：辅助身份 JSON **数组**，每行恰好四个字段
  `id / age_min / age_max / postal_prefix`：
  - `id`：非空白、去空格后与自身相等、≤128 字符，数组内唯一；
  - `age_min`、`age_max`：整数且 `0 <= age_min <= age_max <= 120`（布尔拒绝）；
  - `postal_prefix`：**0..5 位 ASCII 数字字符串**（允许空前缀，允许前导零）。
- `--audit-db`：私有 SQLite 审计库路径，含辅助 id 与推断结果，**绝不放入公开目录**。
  三个路径必须互不相同；审计库路径拒绝符号链接；不是本工具审计库的现有 SQLite
  文件拒绝打开。

两个输入文件沿用 8 MiB 严格 JSON 限制（拒绝重复 JSON 键、`NaN/Infinity`），
原始字节的 SHA256 随每次运行双源保存。退出码：成功 `0`，任何非法输入或存储冲突
`2`（stderr 给出原因）。**全部校验与求解在内存中完成、通过后才打开审计库**，
因此非法输入退出 2 时旧库字节保持不变；首次运行即失败则不会创建数据库文件。

## 假设（必须成立，违反即非法输入）

1. 辅助表**恰好**包含全部已发布身份：辅助行数必须等于报告 `released_count`
   （即全部容量槽容量之和）。数量不一致直接退出 2，而不是记 Hall 失败——不猜测
   辅助表缺失或多出身份时的概率分布。
2. 辅助 `id` 唯一，仅在审计库内作为身份键使用，不出现在 stdout。
3. 公开报告本身可信、未被篡改：报告内 `released_rows` 与 `equivalence_classes`
   两套计数必须逐桶、逐 category、总计完全一致，否则退出 2。

## 威胁模型（刻意收窄）

审计回答且仅回答一个问题：**在“每人恰好占一个容量槽、所有容量恰好填满”的全部
可行分配（满匹配）空间上，公开桶标签与辅助区间/前缀的交集会把哪个 category 强制
到某个身份上？**

- 公开 `(age, postal, category)` 计数被建模为**容量槽**：每个不同三元组一个槽，
  容量是该三元组的重复行数。重复槽位**不展开**成副本节点。
- 连边只看年龄与邮编：辅助年龄区间与桶 age 标签相交、且邮编前缀与桶 postal 标签
  相交时，身份与该桶内**每个 category 槽**连一条兼容边。category 不参与连边。
- 结论是确定性的集合论结论，**不使用任何概率、先验或随机模型**：
  - 某身份在**所有**满匹配中只能取同一个 category（可能类别集合大小恰为 1）时，
    记一次**强制暴露**（forced exposure），保存该 category；
  - 一条兼容边若不属于**任何**满匹配，标记 `usable=0`；属于至少一个满匹配则
    `usable=1`（流当前选中的匹配边恒为可用）；
  - 不存在满匹配时运行状态为 `inconsistent`，保存 Hall 证据，不产生任何身份类别
    推断，也不编造概率。
- 明确**不承诺**：辅助信息本身的真实性、桶外背景知识攻击、跨多份报告的联合攻击、
  成员关系推断、差分隐私或法律去标识认证。同桶不同 category 的槽共享完全相同的
  age/postal 标签，因此仅靠桶标签无法在同桶内区分 category 槽——这是模型的固有
  界限，工具不会用启发式规则越过它。

### 标签相交语义（含年龄 120、`*` 与前导零）

- age 标签三种：精确年龄 `"37"`（含 `"0"`、`"120"`，拒绝前导零写法）、规范十岁段
  `"20-29"`…`"110-119"` 与 120 单点 `"120-120"`、通配 `"*"`。区间相交为闭区间
  相交；`"*"` 与一切相交。
- postal 标签三种：完整五位 `"00123"`（前导零是普通数字）、三位茎 + `"**"` 如
  `"001**"`、通配 `"*"`。两个定长数字串相交当且仅当其中一个是另一个的前缀
  （公共前缀非空）；空前缀与 `"*"` 与一切相交。注意桶标签只承诺三位茎时，五位
  辅助前缀不能排除该桶——桶内真实邮编可能以该茎加任意后缀开头。

## 求解算法（不枚举匹配、不逐边重求解）

二分图左为身份（至多 2000），右为容量槽（槽数至多等于身份数），源/汇各一。

1. **一次 Dinic 最大流**：源→身份容量 1，槽→汇容量为槽容量，兼容边容量 1。
   最大流等于身份数当且仅当存在满匹配。
2. **Hall 证据**：最大流不足时，在残量网络里从源做可达搜索。可达身份集合 `X`
   与可达槽集合 `N(X)` 满足 `|N(X) 的联合容量| < |X|`（这些槽的入边全部饱和），
   缺口 `deficit = |X| - cap(N(X))` 即 Hall 不等式的违反量。保存 `X` 的身份 id、
   `N(X)` 的槽及其容量与缺口。
3. **允许边 SCC 分析**：满匹配存在时，在身份+槽节点上构造交错残量有向图——未用
   兼容边身份→槽，已匹配边槽→身份。迭代 Kosaraju 求强连通分量：一条未用边属于
   某个满匹配，当且仅当两端在同一 SCC（匹配边天然可用）。全程**一次流 + 一次
   SCC + 一次可达搜索**，不枚举任何匹配，也不为每条边重跑最大流。
4. 每个身份的可能 category = 其全部可用边所到槽的 category 集合；集合大小为 1
   才记强制暴露。

支持规模：**2000 身份、20000 兼容边**（超出即退出 2）。规模测试在该上限下端到端
运行并断言时限；小图另以回溯穷举（仅在测试中展开槽位副本）逐身份、逐边对照
SCC 结论与 Hall 证据。

## 私有审计库表结构

| 表 | 内容 |
| --- | --- |
| `meta` | 键值，含 `audit_schema_version` |
| `runs` | 每次运行一行：自增 `run_id`、报告与辅助双源 SHA256、状态 `consistent/inconsistent`、身份/槽/边计数、总容量、最大流、UTC 时间戳 |
| `slots` | `(run_id, slot_index)`：桶 age/postal 标签、category、容量 |
| `edges` | `(run_id, identity_index, slot_index)`：`matched`（流是否选中）与 `usable`（是否属于某个满匹配；inconsistent 行为 NULL） |
| `identity_outcomes` | `(run_id, identity_index)`：辅助 id、原始 age_min/age_max/postal_prefix、`forced_exposure` 0/1、`forced_category`（非强制为 NULL） |
| `identity_possible_categories` | `(run_id, identity_index, category)`：该身份在全部满匹配中可能取到的每个 category 一行 |
| `hall_witnesses` | inconsistent 运行每运行一行：证据身份数、邻接槽数、邻接联合容量、缺口 |
| `hall_witness_identities` | Hall 证据中的身份 index 与 id |
| `hall_witness_slots` | Hall 证据中的槽 index 与容量 |

一次运行的全部行在**单个 `BEGIN IMMEDIATE` 事务**内提交，失败回滚，旧运行与旧库
不受影响。运行只追加（同输入重复执行产生两个独立 `run_id`，双源 SHA 相同，便于
对账），不更新或删除历史运行。审计库含辅助 id 与个体推断，按私有数据保管。

## stdout 与脱敏

stdout 输出一行紧凑 JSON，仅含聚合信息：`run_id`、双源 SHA、报告内嵌源 SHA、
状态、身份/槽/边/容量/最大流计数、强制暴露人数、不可用边数，以及 inconsistent 时
的 Hall 证据**尺寸与缺口**（不含身份 id）。身份级数据（id、可能类别、证据身份
集合）只落在私有审计库；stdout 与任何公开产物都不含辅助 id 或个体映射。

## 非目标与运维假设

- 不读取 v1 私有源表、不读取 series 台账；不做跨报告、跨轮次关联。
- 不加密审计库、不管理文件权限；私有目录访问控制由操作者负责。
- 单写者假设；`busy_timeout` 只覆盖短暂锁竞争，并发写入不在承诺范围内。
- 运行时仅用 Python 标准库（含 `sqlite3`）。
